# رفع النظام على دومين واستضافة — خطوة بخطوة

الطريقة: **خادم واحد (VPS)** يعمل عليه كل شيء داخل Docker:
التطبيق + قاعدة البيانات + شهادة HTTPS تلقائية (Caddy) + نسخة احتياطية يومية.

> الملفات الجاهزة في المستودع: `Dockerfile`، `docker-compose.yml`، `deploy/Caddyfile`، `deploy/env.production.example`.

---

## 1) ما تحتاج شراءه

| البند | المواصفات المقترحة |
|---|---|
| خادم VPS | Ubuntu 24.04، معالج 2 vCPU، ذاكرة 4GB، مساحة 40GB على الأقل. (مثل Hetzner أو DigitalOcean أو مزود سعودي) |
| دومين | مثل `pamperme.sa`، ويُفضّل نطاق فرعي للنظام مثل `app.pamperme.sa` |

> **بيانات العميلات:** النظام يحفظ أسماء وأرقام وعناوين عميلات ورواتب. راجعوا متطلبات نظام حماية البيانات الشخصية في السعودية (PDPL) عند اختيار مكان الخادم؛ الاستضافة داخل المملكة قد تكون الأنسب. (هذه ملاحظة وليست استشارة قانونية.)

## 2) ربط الدومين بالخادم

من لوحة الدومين (DNS) أضف سجلًا:

| النوع | الاسم | القيمة |
|---|---|---|
| `A` | `app` | عنوان IP الخادم |

انتظر حتى يعمل (عادة دقائق، وأحيانًا حتى ساعات).

## 3) تجهيز الخادم (مرة واحدة)

ادخل للخادم عبر SSH ثم:

```bash
# تثبيت Docker
curl -fsSL https://get.docker.com | sh

# جدار الحماية: SSH و HTTP و HTTPS فقط
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable

# تنزيل النظام (المستودع خاص: استخدم Deploy Key أو Token للقراءة فقط من GitHub)
git clone https://github.com/tafra2026/system.git /opt/pamper
cd /opt/pamper
```

## 4) الإعدادات السرية (على الخادم فقط)

```bash
cp deploy/env.production.example .env
openssl rand -base64 32      # انسخ الناتج ككلمة مرور قاعدة البيانات
nano .env
```

املأ:
- `DOMAIN=app.pamperme.sa` (بدون https)
- `POSTGRES_PASSWORD=` الكلمة الطويلة العشوائية من الأمر السابق
- `GOOGLE_MAPS_API_KEY=` (اختياري، لاحقًا)

> ملف `.env` لا يُرفع إلى GitHub ولا يُرسل في المحادثات.

## 5) التشغيل

```bash
docker compose up -d --build
docker compose ps            # يجب أن تكون كل الخدمات Up
```

- أول تشغيل يستغرق عدة دقائق.
- تحديثات قاعدة البيانات تُطبّق تلقائيًا عند كل تشغيل.
- شهادة HTTPS تصدر تلقائيًا بعد أن يشير الدومين للخادم.

## 6) البيانات الأساسية وأول حساب (المالكة)

```bash
# الموظفون الثمانية والخدمات والباقات ونقطة الانطلاق (آمن للتكرار)
docker compose exec app npm run db:seed

# حساب المالكة: سيطلب كلمة المرور مرتين (لا تظهر أثناء الكتابة)
docker compose exec app npm run account:create -- --role=owner --username=doha
```

الآن افتح `https://app.pamperme.sa` وسجّل الدخول.

## 7) حسابات باقي الموظفين (من داخل التطبيق)

**الموظفون ← اختر الموظف ← حساب الدخول:**
1. اكتب اسم المستخدم (إنجليزي صغير، مثل `alaa`).
2. اكتب كلمة مرور (10 أحرف على الأقل) وأعدها للتأكيد.
3. الخيار «يغيّرها الموظف بنفسه عند أول دخول» مفعّل افتراضيًا (مستحسن).
4. «إنشاء الحساب»، ثم سلّم البيانات للموظف **بشكل خاص**.

- نسي كلمة المرور؟ من نفس المكان: «تعيين كلمة مرور جديدة».
- نسيت المالكة كلمة مرورها؟ على الخادم:
  `docker compose exec app npm run account:create -- --role=owner`
- موظف غادر؟ «إيقاف الحساب» (لا يُحذف تاريخه).

## 8) التحديث عند وجود نسخة جديدة

```bash
cd /opt/pamper
git pull
docker compose up -d --build
```

## 9) النسخ الاحتياطي

- نسخة تلقائية كل يوم في المجلد `/opt/pamper/backups`، وتُحذف النسخ الأقدم من 30 يومًا.
- **انسخها خارج الخادم أيضًا** (مثلًا أسبوعيًا إلى تخزين مشفّر)، لأن الخادم نفسه قد يتعطل.
- نسخة فورية يدويًا:
  ```bash
  docker compose exec -T db pg_dump -U pamper -Fc pamper > backups/manual-$(date +%Y%m%d).dump
  ```
- الاستعادة (تمسح البيانات الحالية وتضع النسخة مكانها):
  ```bash
  docker compose exec -T db pg_restore -U pamper -d pamper --clean --if-exists < backups/pamper-XXXX.dump
  ```
- جرّب الاستعادة على خادم تجريبي مرة كل شهر.

## 10) أوامر مفيدة

| المطلوب | الأمر |
|---|---|
| حالة الخدمات | `docker compose ps` |
| سجل التطبيق | `docker compose logs -f app` |
| إعادة التشغيل | `docker compose restart app` |
| إيقاف الكل | `docker compose down` (البيانات تبقى) |

## ما تم اختباره وما لم يُختبر بعد

- ✅ صورة التطبيق تُبنى وتعمل: تحديث قاعدة البيانات تلقائيًا، التهيئة، إنشاء حساب المالكة، تسجيل الدخول.
- ⏳ تشغيل Caddy وشهادة HTTPS الحقيقية تُختبر على الخادم الفعلي مع الدومين (تحتاج دومين حقيقي يشير للخادم).
- ⏳ تابي وتمارا: ما زالت تُسجل يدويًا حتى تفعيل التكامل.
- ⏳ الإشعارات على الجوال (Web Push): لاحقًا.

> قبل الاعتماد الكامل: تجربة أسبوع مع الفريق على بيانات تجريبية (`is_test`)، ثم البدء بالبيانات الحقيقية.
